# Buyer evidence index

Use this index to distinguish a public reference from evidence about a proposed or delivered engagement. Public documents explain an approach. Project-specific records establish whether that approach was applied.

| Question | Public starting point | Evidence to request for a real engagement |
|---|---|---|
| Is the scope clear? | [Worked pilot brief](pilot-brief.md) | Agreed scope, exclusions, systems, responsibilities and change process |
| Can the workflow be inspected? | Reference implementation and its documented limitations | Relevant revision, reproducible setup, representative sample inputs and outputs |
| Are approvals enforced? | [Acceptance checklist](../templates/acceptance-checklist.md) | Tests for missing approval, stale approval and prohibited actions |
| What happens when integrations fail? | [Runbook](../templates/operations-runbook.md) | Failure/retry evidence in the agreed environment and a named recovery owner |
| Where will our data go? | [Data and supplier record](../templates/data-and-suppliers.md) | Completed data flow, permissions, provider configuration and retention/deletion decisions |
| What exactly are we accepting? | [Requirements](../templates/requirements.md) | Written criteria, evaluation report, unresolved issues and business-owner decision |
| Will our team be able to operate it? | [Handover checklist](../templates/handover-checklist.md) | Access ownership, recovery rehearsal, dependency record and agreed support scope |
| Are the claimed outcomes substantiated? | [Case study template](../templates/case-study.md) | Baseline, measurement period, calculation method, attribution and permission to disclose |
| How is responsibility handled after launch? | [Support and change template](../templates/support-and-change.md) | Executed scope, response arrangements, exclusions and escalation contacts |

## Evidence that should remain private

Customer data, access credentials, contracts, employment or education documents and non-public system details should be exchanged through an agreed private channel. An anonymised public narrative can be accompanied by more detailed private verification where the relevant parties permit it.

## Reading a reference result

A reproducible local demo can support a narrow claim such as “this revision rejected an unapproved handoff on these synthetic inputs.” It cannot by itself support claims about production availability, model accuracy on customer data, compliance, customer adoption or realised savings. Ask for the evidence that matches the claim.
